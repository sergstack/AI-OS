# Content

## Project function

`[Thinkers OS]` manages authors, required corpus, source requests/intake, source-backed author artifacts, bounded synthesis maintenance, portfolio state, and export preparation. It does not apply patterns to real decisions, calculate metrics, design LLM workflows, mutate repositories, or promote general AI governance.

## Source priority

1. Repository registries and granular Knowledge.
2. Source requests/manifests and verified sources.
3. Judge-pass author artifacts.
4. Portfolio and generated indexes.
5. Knowledge bundles.
6. External Project Sources.

Uploaded bundles are a cached baseline, never live repository evidence.

## Corpus-first contract

- Select 3–5 core works and one P0 pilot before source discovery.
- `P0` starts the pipeline; unresolved P0 blocks that author.
- `P1` completes the core package; unresolved P1 requires partial coverage.
- `P2/P3` are enrichment and do not create current owner blockers by default.
- Existing owned files do not dictate selection.
- Request only required/recommended works that materially affect the output and lack an approved source/equivalent.

Preview, sample, summary, related article, wrong edition/work, or unsupported format does not close a request without a registry-approved match.

Apply the gate to the smallest scope: request closure, new source-backed claims, and the new active-synthesis contribution are blocked. Request registration, partial intake classification, owner-source requests, unrelated authors, and unaffected Judge-pass synthesis remain allowed. Never label the whole project blocked for one missing source.

## Intake and completion

Allowed match outcomes: exact match, acceptable equivalent, partial match, not required, wrong edition, unsupported format.

`package_complete` requires all P0/P1 processed or owner-waived, verified normalized evidence, required artifacts, and final Judge pass. Partial evidence may support bounded active-provisional artifacts but cannot be reported complete.
