# Post-Fix Learning Review: Стабилизация DeepSeek judge через schema-mode + сохранение fallback/metadata

## 1. Status

**Status:** success

**Что исправлено:**
* `deepseek-r1:32b` оставлен как primary judge.
* Пустой ответ DeepSeek классифицирован как runtime/model behavior при low-budget/plain вызове.
* Judge-вызов переведён на существующий `JUDGE_RESULT_SCHEMA`.
* Fallback на `mistral-small:latest` сохранён.
* Metadata теперь фиксирует попытки judge, primary failure и fallback details.

**Почему фикс считается успешным:**
* Direct smoke подтвердил, что plain low-budget вызовы DeepSeek могут возвращать empty response, а JSON/schema mode возвращает валидный JSON.
* Targeted tests: 49 passed.
* Full pytest: 213 passed, 3 skipped.
* Не менялись thresholds, scoring, routing config, Kestra, narrative, mart/business logic.

**Недостающее evidence (отсутствующие улики):**
* Не было live Kestra run после schema-mode фикса.
* Не подтверждено поведение DeepSeek в production-container через `host.docker.internal` после фикса.

## 2. What Worked

| Factor | Why it helped | Evidence |
|---|---|---|
| Direct Ollama smoke до фикса | Отделил проблему модели от проблемы pipeline/parser | plain low-budget вернул empty response, JSON/schema вернул content |
| Проверка reduced judge prompt | Показала, что parser и judge prompt не являются основной причиной | reduced judge prompt в schema mode вернул valid JSON |
| Schema-mode для judge | Заставил DeepSeek отдавать структурированный verdict, а не уходить в reasoning-only | `JUDGE_RESULT_SCHEMA` дал валидный JSON |
| Сохранение fallback на mistral-small | Убрал single point of failure | fallback behaviour preserved |
| Metadata-only фиксация failure/fallback | Сделала runtime диагностируемым без загрязнения status_reasons | attempted judge models, fallback reason, primary empty-response error |
| Full pytest | Подтвердил отсутствие регрессии в тестовом контуре | 213 passed, 3 skipped |

## 6. Learning Rule

```text
Learning Rule:
Reasoning-модели в production judge нельзя вызывать как свободный plain-text output, если от них требуется контрактный verdict. Для judge используй schema/JSON mode, fallback и обязательную metadata-трассировку primary/fallback.

Why:
DeepSeek оказался работоспособным, но нестабильным в plain low-budget режиме: модель могла потратить output budget на reasoning и вернуть empty response. Schema-mode превратил judge из “рассуждающей модели” в контрактный validator.
